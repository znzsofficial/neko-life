# Neko Life

**让麦麦有自己的好奇心，而不只是等你说“帮我搜一下”。**

MaiBot插件：在批准的公开兴趣中自主选题，搜索、阅读、留下有来源的见闻，并用连贯的角色日程丰富聊天。
探索、主动分享、绘图各有边界，不把看过网页等同于必须发消息。

0.5把已有的具体角色场景、晨间梦境、晚间感想和公开见闻接入同一候选流程；只复用已生成素材，不每次检查额外调用模型。继续由原主动插件择机发言，不广播日程、不补播错过的生活。专业笔记可以保存但不适合群聊开场，连续研究同一问题支线后要求换线。

**主动分享需要neko-proactive-mai≥2.2及宿主现有`maisaka.reply.after_send`精确Hook（neko-reply-latency-v1配套）**。采用时由Planner选择`reply.plugin_options["neko.life.share"]={"receipt_id":"本次候选编号"}`；明确不采用用`neko_life_skip_share`。扩展在真实回复执行中绑定session/reply/call，普通QQ引用或正文相似度不证明送达。没有此Hook的上游不能靠强制兼容跳过注册，须先评估配套；本次维护不增加新的宿主补丁。

0.4.4支持共享Focus：从宿主reply工具路由的session_id枚举取有界成员，逐个执行原生活背景授权，只用对应聊天的独立宿主消息前缀判断相关性。注入背景标注目标，整轮最多600字；无可信路由/未知来源或撤权就跳过，不把某群身份套给全局，不放宽工具/私聊权限。普通Replyer和单会话行为保持，不新增模型/发言/配图。

## 能做什么

- **自己探索**：从批准兴趣和未解问题选题，读取少量公开资料；没价值可以跳过，不每天机械换关键词。
- **记住见闻**：短笔记区分资料摘要与个人看法，保留来源、获取时间及“正文摘录/搜索摘要”标记，后续可以继续追问。
- **有生活节奏**：人格一致的每日角色日程、临近场景、轻量精力和情绪；不是现实经历证据，不因“睡觉”拦用户消息。
- **择机分享**：生活和见闻轮换提供一个候选，沿用原主动目标、概率、时段和冷却，由Planner决定是否说。Life另有每日上限和分享间隔，不是必须完成的任务。
- **管理可见**：工作区查看日程、查询、笔记、回执和用量，暂停/恢复、确认后清理，或显式探索一轮只记笔记。

可选梦境/短日记默认关闭；只属于角色素材，不读取私聊原文或写入宿主长期记忆。

## 与现有插件协作，不再造一套

| 插件 | 分工 |
| --- | --- |
| **Neko Life** | 日程、选题、探索编排、笔记和候选 |
| **neko-web ≥1.6.1** | 搜索、公开正文读取、供应商凭据与网络防护 |
| **neko-proactive-mai ≥2.2.0** | 唯一主动聊天调度器、目标和候选协作 |
| **neko-draw ≥1.3.0** | 授权后可自主配生活环境插画；自画像仍先查外貌记忆 |
| **TTS / 视频** | 保持独立，不被Life改写回复或接管发送 |

没有Web/主动插件时，日程与其他独立插件仍可运行。Life没有自建浏览器、绘图或语音引擎。

## 安装与启用

需要 **MaiBot ≥1.3.11、SDK ≥2.12、Python ≥3.12**，以及上方说明的现有精确发送Hook。

1. 从Release下载`neko-life-<version>.zip`，按`checksums.txt`核对SHA256。
2. 解压到宿主`plugins/neko-life/`，根目录应同时包含`plugin.py`、`_manifest.json`及`neko_life/`。
3. 在WebUI检查配置。**新安装默认关闭**，管理员名单为空时拒绝管理命令。
4. 需要自主上网时，按[协作指南](docs/integration.md)显式配对能力密钥，再分别开启Web后台接口和Life探索。
5. 在聊天背景、主动分享、自主配图各组分别填QQ群号或私聊QQ号；已有宿主会话ID仍放在“高级”字段。

插件ID为`neko.life`。配置和`life.db`存于宿主分配的独立data_dir，不在源码中。
配对脚本默认只预览，已有正确凭据不轮换，不输出密钥，也不会自动开启任何功能。

### 关键配置

0.4.1起，设置页按探索、聊天背景、主动分享、自主配图、后台模型和每日用量显示中文分组/字段名。
时间是北京时间24小时制；探索间隔单位是分钟，配图间隔是秒（1800秒=30分钟）。每日用量填0为不限。
0.4.3起可直接填QQ群号/私聊QQ号；三种功能独立授权，原有`sessions`保留为高级兼容且继续生效。
号码只通过宿主已有QQ会话查询核验，不创建会话、不猜ID。下表保留配置键方便对照文件。

| 配置 | 含义 |
| --- | --- |
| `plugin.enabled` | 总开关，默认关闭 |
| `models.enabled / task` | 允许额外模型调用；task是宿主任务名，默认utils |
| `explore.enabled / interests / exclusions` | 是否自主探索、批准的公开兴趣和禁区；兴趣为空不探索 |
| `explore.start / end / interval_minutes` | 默认09:00–23:00、每120分钟；起止相同为关闭时窗，间隔最少5分钟 |
| `context.enabled / group_ids / user_ids / sessions` | 聊天背景与近期笔记；三份名单都空不注入 |
| `sharing.enabled / group_ids / user_ids / sessions` | 公开分享候选，仍须通过原主动白名单和调度规则 |
| `sharing.daily_max / interval_minutes` | 每会话每日最多2次、至少间隔180分钟；未知保守占一次，可配置，不改变主动检查频率 |
| `sharing.unknown_max` | 每会话未知积压最多8条（含历史）；达到后暂停新分享，不清历史或重发 |
| `context.drawing_context` | 仅补充明确绘图请求的角色场景，不授权自主画图 |
| `drawing.enabled / group_ids / user_ids / sessions` | 独立授权Planner自主配生活环境插画；Draw侧`life.sessions`仍须授权同一宿主会话并配对密钥 |
| `drawing.cooldown_seconds` | 持久防刷屏间隔，默认1800秒、最少300秒；不设每日生图成本上限 |
| `memory.dreams / diary` | 可选虚构片段，默认关闭，使用统一模型预算 |
| `admin_users` | 私聊管理QQ白名单，空名单拒绝 |

### 群号 / QQ号与旧配置迁移

`context`、`sharing`、`drawing`每组均新增`group_ids`（QQ群）和`user_ids`（仅私聊）两项字符串列表。
例如`group_ids = ["123456789"]`；每项纯ASCII数字、无空格/前导零/`qq:`，每类最多16项。
相同号码分别填群/私聊字段不会相互授权；只支持QQ平台。各组的`enabled`和总开关仍须开启。

- **升级不必迁移**：新字段默认空，原`sessions`完整保留且仍按精确ID授权，不额外要求旧ID能被查询。
- **号码与旧ID取并集**，不是覆盖：先通过宿主只读查询确认号码对应的已有会话，再由管理员按需删除该组旧ID。
  撤权须删除该功能所有对应号码和旧ID；只删号码但保留旧ID仍有效。不会自动改写其他功能或现场配置。
- 只查已有会话，未联系过/未载入的目标、接口异常、格式/类型/平台矛盾、超时均拒绝。
  可在已有聊天收到新请求后重试；不要使用`chat.open_session`补建。号码查询只返回首条路由时，补查一次已有QQ会话列表，
  精确核对当前不透明session的类型/目标/平台（最多512条，重复或不明确拒绝），不猜编码、不创建会话。
- 可选`account_id`为高级“限定机器人QQ账号”，空值不额外限定；填写后只允许该机器人账号的号码路由。
  多机器人迁移应填写原授权账号，以免一个群号扩大到另一机器人。它不是聊天对象QQ号，也不替代群/私聊名单；旧高级sessions仍是独立兼容授权。
- Draw仍双侧授权：Life的`drawing.group_ids`不替代Draw的`life.sessions`，也不会开启Draw开关、轮换密钥或花费生图额度。
  主动分享仍受主动插件目标、概率、时间窗与冷却限制；没有新调度器。
- 每次请求重读当前授权、不跨请求缓存；每组最多32次目标lookup加1次有界已有会话查询、总时限2秒；同一次背景构造可复用查询。
  热更上述权限字段不会重建日程任务；已提交的外部任务不能撤回，未知任务仍不重放。日预算`0=不限`保持不变。
- 工作区“聊天授权核验”和私有`status_v1.authorization`显示各功能最近一次核验结果（不是全名单预检）。
  `lookup_unavailable_or_invalid`表示宿主无已有会话/查询不可用/返回矛盾，`lookup_timeout`表示超时；
  `invalid_qq_target`表示格式/数量错误，`configuration_changed`表示查询期间撤权。
  状态不输出QQ号、会话ID、查询响应正文或密钥。

本次仅使用合成数据/真实SDK代理做离线测试，不代表线上目标已解析或QQ投递已验收；真实配置由部署管理员单独迁移。

### Token充裕时，可以关闭日成本预算

`budget.rounds/search/read/model/input_units/output_units`每项均支持 **`0=不限`**。
同时检查neko-web的`automation.daily_search_max/daily_read_max`，避免另一层日额度仍挡住检索。
默认安装保留可调整的保守额度，不替每位部署者默认选择无限费用。

关闭日预算**不会关闭**并发、超时、单轮请求与正文数、输入/响应大小、故障退避、去重和聊天防刷屏。
实际/未知用量继续记录。正数预算会预留和结算；隐藏推理、续写、未知用量及搜索供应商价格使插件无法承诺精确金额封顶。

## 使用与管理

普通聊天可以问“你最近看了什么”，Planner可调用只读工具`neko_life_recent`。
相关背景按当前允许会话提供，不把整本笔记库塞进提示。

开启双方独立配图授权后，Planner可以按需选择`neko_life_draw_scene`，无需用户逐次要求。
它只使用当前角色场景生成**无人环境插画**，不发送原聊天/人格全文，不编造人物外貌。
自画像/改图仍走原工具和外貌记忆流程。没有第二套发图定时器，不要求每次聊天/探索都出图。
同一场景防重、跨场景冷却、签名及执行端持久幂等共同生效；结果未知不自动补发或换工具重画。

私聊管理员命令：

| 命令 | 用途 |
| --- | --- |
| `/neko-life status` | 状态、错误、探索和用量 |
| `/neko-life schedule` / `notes` | 日程或来源笔记 |
| `/neko-life pause` / `resume` | 暂停或恢复后台任务 |
| `/neko-life plan HH:MM HH:MM 内容` | 修改现有未来节点，起止须匹配日程；不改过去与当前 |
| `/neko-life replan` | 明确要求模型重新生成未来节点，使用同一预算 |
| `/neko-life clear` | 先取得60秒确认令牌，再确认清理当前人格笔记/问题；保留预算与审计，有未确认归因时拒绝 |

工作区的“探索一轮，只记笔记”需要确认，会调用真实服务，但不强制发QQ；保留独立5分钟防连点。
自主探索本身可以选择不保存、不分享。

## 已验证与明确边界

- 已核实宿主1.3.9/SDK2.12的manifest、WebUI和包含图片/工具配对的Context Items协议；CI测试不同系统与Python版本。
- 已完成一次真实Exa搜索→两篇NASA官方正文→来源笔记。该次由管理员指定主题，不冒充自主选题或证明供应商持续可用。
- 0.5离线组合已区分候选提供、明确采用/不采用及传输结果；仍不冒充真实群使用验收。**提交不等于送达**：部分发送/超时/缺回执保持unknown，不重发、不按正文猜测；精确成功也只证明传输，不保证模型表达忠实或QQ客户端已显示。
- 桌面1440px和手机390px的工作区已检查，长笔记使用全宽正文；宿主自身活动浮层可能暂时遮住手机底边。
- **0.4起支持经独立授权的自主生活环境插画**：执行端验签、会话白名单及持久幂等，不再靠提示词判断调用来源。新装默认关闭，普通生图工具不受此开关影响；不将插画冒充实拍/新闻证据。
- 追加授权后已用部署版本和真实供应商完成一次场景生成，并核验重复调用被拦截；验收进程仅将发送结果捕获为私有图片，未额外向QQ发图，不冒充客户端投递验收。

搜索最多4条来源、每轮最多读取2篇正文；正文≤2MiB/4000字，不执行网页脚本或取图。
截断不等于读完整篇，摘要可能出错，来源不明的日期保持未知。外部资料始终不可信，不能变成工具执行指令。

背景上限Planner600字、Replyer300字，仅替换自身标记，不删历史、原文或其他插件背景；Hook不联网/调模型。

生活背景不再常驻追加“已授权按需用neko_life_draw_scene…”等工具操作尾注（Planner/Replyer均移除）；保留当前生活场景、相关见闻及用户明确绘图时的条件场景参考。配图工具仍独立注册、执行时独立授权/去重；删除尾注不关闭自主配图，也不修改任何线上名单或参数。
旧快照超过15分钟不注入，笔记查询检查当前有效记录。宿主16MiB聚合Hook限制不变。

数据库损坏或未知schema时保留原文件、暂停写入，不自动建空库。备份需覆盖私有data_dir，
不要把密钥、数据库、聊天、日志或带身份的截图放进Git、Release或Issue。详见[SECURITY](SECURITY.md)。

## 开发

```bash
python -m pip install -e ".[test]"
python scripts/test_suite.py
python -m ruff check .
python -m ruff format --check .
python scripts/build_release.py
```

模块按存储、预算、模型路由、探索、日程、背景、能力桥和SDK接入分离。测试使用合成数据和假服务，
不登录账号、不调用真实模型或QQ。生态组合测试需要相邻源码目录，CI显式检出固定SHA；不得借用相邻最新开发分支。
CI为Linux/Windows × Python3.12/3.14 × SDK2.12.0/最新2.x共8档；`test_suite.py`要求至少106项并禁止任何skip。生态固定版本已更新到本轮修复后的主动/Web/Draw/TTS提交；主动测试显式配置当前授权，不用旧白名单行为凑通过。Actions固定官方SHA，构建最终ZIP后从临时解压目录真实导入SDK插件，已验包与摘要作为14天CI artifact留存；不自动发布Release或部署，CI不包含真实配置/Key/DB。
本地可用`NEKO_LIFE_ECOSYSTEM_ROOT`指定按同一固定SHA导出的四个插件快照目录。普通unittest可显示skip，但不能当完整验证。
Release使用文件允许列表及固定ZIP元数据，可重复构建，不包含配置、数据库、能力密钥或截图。
