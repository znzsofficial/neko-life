# Neko Life

让麦麦在明确预算内探索公开资料，留下有来源的见闻，并拥有连续的角色日程。

**0.1.0为分阶段交付版本，首次安装全部新增行为默认关闭。** 当前已有探索闭环、日程/轻量状态、相关背景和可选主动候选接口；不是一键全自动代理。真实供应商、模型、QQ及绘图效果需要按阶段单独验收。

## 职责

- Life：批准兴趣→自主选题→有界搜索/阅读→带来源的短笔记→有限期未解问题/分享候选。
- neko-web：继续负责搜索供应商、公开文本下载、密钥和公网安全防护。
- attention-seeker-mai：仍是唯一主动聊天调度器，保留群私目标、概率、时段、冷却和原意图。
- neko-draw / TTS / video：保持独立；Life不直接自主发送聊天、图像或语音。

默认不采集私聊主题，不建立“唯一主人”或关系好感度，不做消息防抖、撤回留存、睡眠拒绝回复、跨群转述、自动登录/发帖/购买或下载运行代码。

## 安装与配置

需要MaiBot1.3.9、SDK2.12以上及Python3.12以上。根目录包含`plugin.py`、`_manifest.json`和`neko_life/`。插件ID是`neko.life`，数据目录由宿主`ctx.paths.data_dir`指定，数据库为`life.db`。

建议顺序：默认关闭安装 → 无模型/无网络影子运行 → 确认供应商费用和预算后只探索记笔记 → 指定会话使用背景 → 明确目标后主动分享。不能因为勾选总开关就默认授权全部收费或发送行为。

主要配置：

- `plugin.enabled`：总开关，默认false。
- `models.enabled`：允许新模型调用，默认false；路由`models.task`默认utils。
- `explore.enabled`：允许搜索阅读，默认false；`interests`必须填写批准的公开兴趣，空列表不会自主探索；`exclusions`是禁区关键词。
- `explore.start/end`：探索允许时窗，默认09:00–23:00，按Asia/Shanghai；相同起止表示不允许。
- `context.enabled/sessions`：只在显式允许的宿主会话ID中注入相关背景，空列表不注入。
- `context.drawing_context`：默认false。只给明确角色绘图请求补充场景和记忆边界，**不是自主配图开关**；不保证模型一定调用绘图工具。
- `sharing.enabled/sessions`：默认false；指定会话才能领取公开见闻候选，还必须被原主动插件允许。主动插件另有`life.enabled`开关。
- `admin_users`：管理QQ号，空名单拒绝管理命令；命令限私聊。
- `budget`：每天探索3轮、搜索6次、读网页6次、模型16次；输入50000/输出8000保守预算单位，可调低，当前版本不能调高突破安全上限。探索间隔至少2小时。
- `memory.dreams/diary`：默认关闭；开启后醒后梦境/晚间短日记使用统一模型预算，只写本插件的虚构片段，不读私聊或写宿主长期记忆。

输入预算按UTF-8字节及协议余量预留，不是供应商精确token账单。每次模型调用先预留当天剩余输出额度，可靠实际用量返回后再结算未用部分；未知用量保留全额预留，不能继续烧预算。max_tokens只表达本次期望上限，供应商可能计入额外推理/续写；因此插件不能保证实际token或金额绝不超额。实际用量超出整个预留包络会冻结后续工作并保留证据；需要管理员审查，不自动解除。失败/超时/外发未知也占预算，重启不重放不确定任务。手动搜索和用户原有绘图不使用Life账本。

## 本机能力桥：需要显式配置

宿主不向API处理器传递可信调用者ID，因此桥使用独立HMAC能力密钥，不能仅凭`caller_plugin_id`授权。

Web接收端data_dir中`automation-keys.json`与Life的`web-client.json`包含同一条`neko.life`能力密钥。Life的`sharing-keys.json`与主动插件的`life-client.json`包含另一条`attention-seeker-mai`密钥。值为独立随机32字节的十六进制文本；文件0600，目录私有，**不写进源码或示例实际值**。

四个文件由管理员在服务器私有目录中单独配对，不由启动代码自动生成，也不进入Git、Release或通用日志。Web还需`automation.enabled=true`。未配置、权限不安全、签名错误或重放都会拒绝。

能力密钥只授权特定操作，不是供应商API Key；同服务账号运行的程序仍能读取本机文件，不提供OS级隔离。不要把这些JSON内容发到Issue或聊天。

详见[协议说明](docs/protocol.md)。端点：`neko.web.automation_v1@1`、`neko.life.sharing_v1@1`。接收端只处理快速提交/查询/取消或本地候选结算，不在RPC中长时间等待搜索。

## 使用边界

搜索最多4条候选，每轮读前2篇公开正文，下载不执行JS、不取图片、不自动改供应商。来源保留URL、发布日期（缺失就未知）、获取时间与snippet/body标记；截断原文不意味着读完整篇。AnySearch只接受已支持的结构化results JSON，普通展示文本会返回unsupported，不猜测错误含义。

笔记将摘要与个人看法分开，引用只能指向本次已有来源。仍不能保证模型摘要绝对准确，多篇转载不构成独立证明。网页内容没有执行工具/系统指令的权限，但提示注入防护不能被宣传成模型永不受影响。

角色日程每天最多生成一次，当前节点最多细化一次，失败保留模板。精力/饥饿/心情本地推进，离线补算最多72小时。全局人格命名空间隔离，默认不写宿主长期记忆；换人格不会自动继承旧日程。

Planner背景≤600字、Replyer≤300字；Hook只读内存快照，无网络/模型调用。仅替换自身标记的独立system项，不删除普通聊天或其他插件内容。背景超过15分钟未刷新不继续注入。中文字符不是token，真实请求大小仍需测量，16MiB宿主限制不变。

主动候选每天每会话最多1条，包括租约/结果未知的保守占用。提交Host任务不等于发送成功；只在能精确归因的真实成功回执后标sent。正常QQ消息锚点无法证明所属任务时保持未知，不猜测、不自动重发。冷场普通主动聊天仍可沿原规则发生，不保证每轮都会使用见闻。

自主配图尚未开放：执行侧尚未验证如何可靠区分明确用户请求与模型自发建议。当前只支持可选的显式请求场景增强；自画像仍先query_memory查外貌，生成图不能冒充实拍/新闻证据。

## 管理命令

- `/neko-life status`：配置、快照、探索任务和当日预留预算。
- `/neko-life schedule`、`/neko-life notes`：查看日程和来源笔记。
- `/neko-life plan HH:MM HH:MM 内容`：只修改现有未来节点的文字，起止时间必须与日程一致；`/neko-life replan`明确请求重新生成未来节点，使用模型预算，过去和当前节点保留。
- `/neko-life pause`、`/neko-life resume`：暂停/恢复后台，仍受原配置开关约束。
- `/neko-life clear`：生成60秒确认令牌，再用带令牌命令清理当前人格笔记/未解问题。保留预算和审计；有未确认投递归因时拒绝清理。清理后保持暂停。

状态不把空记录冒充接口成功，不把unknown投递冒充沉默，也不把配置时窗当保证会执行的时间表。

数据库损坏或schema未知时保留原文件、暂停写入，不自动建空库。任务细节7天、调用元数据30天、普通笔记90天；在途归因不在自动清理中被随意删除。独立数据库必须单独备份；现有面板备份不自动覆盖MaiBot data。

## 开发与验证

```bash
python -m unittest discover -s tests -t . -q
ruff check .
ruff format --check .
python scripts/build_release.py
```

测试使用合成网页/身份、假模型及假回执。三插件协议测试需要旁边有neko-web和attention-seeker-mai源码及真实SDK，缺失时明确skip。不得把skip当协议验收通过。

管理WebUI提供只读状态、日程、探索、笔记来源和预算；暂停/配置/清理通过私聊命令或宿主设置进行，不提供伪按钮。待验收项包括真实搜索正文闭环、QQ/TTS任务归因、管理页桌面/移动视觉及自主配图可信授权。隔离测试通过不代表这些真实路径全部通过；以计划勾选及交接记录为准，不因0.1可运行就宣布完整计划完成。
